### Сундук Minecraft

Вы храните ресурсы в одиночном сундуке. В Minecraft у такого сундука **27 ячеек** (3×9). В одной ячейке может лежать не больше **64** одинаковых предметов (стак). Данные сундука лежат в `chest.json` и должны сохраняться между запусками.

**Файлы**

- `items.go` — константы и список разрешённых предметов
- `slot.go` — одна ячейка и её методы
- `chest.go` — сундук и его методы
- `storage_iface.go` — интерфейс `Storage`
- `storage.go` — загрузка и сохранение JSON
- `main.go` — ввод команд и вывод

**Поведение программы**

1. Загрузить сундук из `chest.json` (`LoadChest`).
2. Напечатать число занятых ячеек и число свободных — каждое с новой строки.
3. Читать команды с клавиатуры в бесконечном цикле, пока не придёт `exit`.
4. После `exit` напечатать три числа — каждое с новой строки: занятые ячейки, свободные ячейки, сумма всех предметов в сундуке.
5. Сохранить сундук в `chest.json` (`SaveChest`).
6. Напечатать содержимое `chest.json` одной строкой.
7. Снова загрузить файл в новую переменную и напечатать из неё занятые и свободные ячейки.

Команды `count` и `find` в `main` выполняйте через интерфейс `Storage`:

```go
var st Storage = &chest
```

**Стаки**

Если в сундуке уже есть `dirt` (60 штук) и вы кладёте ещё 100:

1. сначала ячейка с `dirt` добирается до 64 (кладёте 4);
2. остаток 96 идёт в пустые ячейки: 64 + 32.

Всё количество должно поместиться. Если места не хватает — ошибка `no_space`, сундук не менять. При `take` если предметов меньше, чем просят — `not_enough`, сундук не менять.

**Команды**

`put`  
Строки: name, count.  
Успех: `ok`. Иначе: `error <текст>`.

`take`  
Строки: name, count.  
Успех: `ok`. Иначе: `error <текст>`.

`count`  
Строка: name.  
Напечатать, сколько всего штук этого предмета в сундуке (сумма по ячейкам).

`find`  
Строка: name.  
Сначала число ячеек с этим предметом, затем строки `index name count` по возрастанию индекса.

`exit`  
Конец цикла команд. Дальше — шаги 4–7.

Неизвестная команда: `error unknown_command`.

**Данные**

`Slot`: `Name`, `Count`. Пустая ячейка — `Name == ""` и `Count == 0`.

Методы ячейки: `IsEmpty`, `FreeSpace`, `SameItem`, `Clear`, `Add`, `Take`.

`Chest`: срез `Slots` длины 27.

Методы сундука: `UsedSlots`, `FreeSlots`, `TotalItems`, `CountItem`, `Find`, `Put`, `Take`.

`Storage`: `CountItem`, `UsedSlots`, `FreeSlots`, `Find`. У `Chest` должны быть эти методы — тогда `&chest` можно передать как `Storage`.

`LoadChest` / `SaveChest` — `os.ReadFile`, `json.Unmarshal`, `json.Marshal`, `os.WriteFile` с правами `0644`. После загрузки длина `Slots` должна быть ровно 27.

Разрешённые предметы уже перечислены в `items.go` (`knownItems`). Там же константы `SlotCount` и `MaxStack`. Функцию `IsKnownItem` допишите сами.

**Тексты ошибок**

- неизвестный предмет — `unknown_item`
- count ≤ 0 — `bad_count`
- не хватает места под весь `put` — `no_space`
- не хватает предметов для `take` — `not_enough`

**Стартовый** `chest.json`

Файл уже лежит в папке: 27 ячеек. Заняты:

- индекс `0` — `dirt` × 60
- индекс `1` — `coal` × 32
- индекс `8` — `iron_ingot` × 64

После запуска файл изменится. Чтобы повторить пример, верните исходный `chest.json` из папки задания (или из git).
